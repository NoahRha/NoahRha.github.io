## 개요

OpenClaw v2026.6.9가 2026년 6월 21일에 올라왔습니다. 이번 릴리즈는 보이지 않는 곳을 단단히 조이는 쪽입니다. 텔레그램이 진짜 리치 HTML을 보낼 수 있게 됐고, 도중에 끊겼던 에이전트 턴이 답을 끝까지 끌고 가도록 복원 로직이 두꺼워졌습니다. Codex 통합은 한 발 더 들어갔고, 외부 프로바이더 플러그인은 npm에서 독립 패키지로 풀렸습니다. 422개 PR이 머지된 큰 릴리즈인 만큼, 매일 쓰는 사람일수록 체감이 큽니다.

## 핵심 요약

- **텔레그램 리치 전달 전면 개선**: 리치 HTML 송신, 마크다운 줄바꿈 유지, 스티커 경로 보존, 진행 중 임시 메시지를 풍부한 프리뷰로 렌더, HTML 표 안전 정규화까지 한꺼번에 들어갔습니다.
- **에이전트 복원력 한 단계 위로**: 사고만 하고 끝난 턴 재시도, 빈 후속 턴 재시도, 컴팩션 이후 사용량 보존, 세션 히스토리 복구, 답장 재정합이 함께 강화됐습니다.
- **Codex 통합 확장**: 플러그인 자동 승인, GPT-5.3 Spark OAuth 라우팅 복원, 원격 노드 `exec`를 동적 도구로 노출, 앱 서버 종료와 터미널 결과 안정화.
- **공식 프로바이더 플러그인 독립**: 외부 프로바이더가 npm 정식 패키지로 발행되고, 외부에 설치된 채널 플러그인이 Gateway 시동 시 자동 로드되며, StepFun이 npm과 ClawHub에서 바로 잡힙니다.
- **클라이언트 확장**: 컨트롤 UI에 세션 워크스페이스 레일과 확장 헬스가 들어왔고, iOS는 Watch 컨트롤, Android는 채팅 컨텍스트 표시가 추가됐습니다.
- **보안 정비**: 디버그·설정 출력의 시크릿 마스킹, 내부 HTTP 세션 오버라이드 차단, 오픈 DM 도구 노출 감사, 플러그인 쓰기 권한 검증을 그대로 유지.

## 본문

### 텔레그램이 진짜 리치 메시지를 보냅니다

이번 릴리즈의 헤드라인은 텔레그램입니다. 그동안 텔레그램이 마크다운을 일부만 흉내 내면서 줄바꿈이 묘하게 뭉치거나 표가 깨져 나오는 경우가 있었습니다. 6.9부터는 텔레그램이 리치 메시지를 리치 HTML로 직접 보냅니다. 마크다운에서 들어온 줄바꿈이 그대로 보존되고, HTML 표는 안전하게 정규화돼서 모바일에서도 깨지지 않습니다.

스티커도 사라지지 않습니다. 이전에는 라우팅 도중에 스티커 미디어 경로를 잃어버리는 사례가 있었는데, 이번에 경로 자체를 보존하도록 다시 짰습니다. 도구 호출이 길게 진행될 때 표시되는 임시 진행 메시지(progress draft)는 단순 텍스트가 아니라 풍부한 프리뷰로 렌더됩니다. 명령 출력도 원문에 가깝게 보여 줍니다.

작은 듯하지만 멘션과 스풀 핸들러가 올바른 전달 경로에 머무르도록 한 수정도 같이 들어갔습니다. 단톡방에서 멘션이 다른 세션으로 새는 듯한 경험을 줄여 줍니다. PID가 재사용되는 상황에서도 ingress 클레임을 복구해, 봇이 죽었다 살아난 뒤에도 진행 중 대화가 끊기지 않습니다.

### 끊긴 턴을 끝까지 끌고 갑니다

이번에 가장 무겁게 들어간 두 번째 축은 에이전트 복원력입니다. 흔하지만 거슬리는 실패 패턴 몇 가지가 동시에 정리됐습니다.

- 사고(thinking)만 하다 에러로 끝난 턴을 자동 재시도합니다.
- 도구 호출 후에 본문이 비어 버린 마지막 턴도 재시도 대상에 포함됩니다.
- 컴팩션이 끼어들 때 사용량 통계가 사라지지 않도록, 새로 채워진 토큰 정보를 그대로 보존합니다.
- 부분적으로 깨진 JSON·히스토리 아티팩트를 자체적으로 복구합니다.
- 답장이 큐에 갇혀 있다가도 최종 응답이 가시화되도록 dedupe 범위를 스레드 단위로 좁혔습니다.

겉으로 보면 "성공했는데 답이 안 보이는" 케이스가 줄어듭니다. 깊이 들여다보면 컴팩션·재시도·세션 시드(seam) 리팩터링까지 함께 들어간 큰 작업입니다.

### Codex 통합이 한 발 더 들어갑니다

Codex 쪽도 굵직한 변경이 많습니다. 우선 플러그인 자동 승인이 들어갑니다. 정책을 미리 통과한 플러그인은 매번 확인 창을 띄우지 않고도 실행될 수 있습니다. GPT-5.3 Spark OAuth 라우팅이 복원되어 Codex의 모델 인증 경로가 다시 자연스러워졌고, 원격 노드의 `exec` 호출이 동적 도구로 노출되어 Codex 안에서 그대로 부를 수 있습니다.

운영 측면에서는 일회성(one-shot) 앱 서버 종료가 깔끔해졌고, 터미널 결과 순서가 뒤바뀌지 않도록 정렬 로직을 손봤습니다. ACP 모델 참조 정규화, 임베디드 런에서 기본 모델 유지 같은 잔잔한 수정도 함께 들어갔습니다.

### 공식 프로바이더 플러그인이 npm에 독립 발행됩니다

생태계 쪽 흐름이 한 번 더 정리됐습니다. 그동안 본체에 묶여 있던 공식 프로바이더가 이제 각자 독립된 npm 패키지로 발행됩니다. 외부에 설치된 채널 플러그인은 Gateway 시동 시점에 자동으로 발견·로드되어, 본체 빌드를 건드리지 않고도 확장이 가능합니다. StepFun이 첫 사례로 npm과 ClawHub 양쪽에서 받을 수 있게 됐습니다.

같은 흐름에서 ClawHub 스킬 설치는 검증된 출처(provenance)를 그대로 보관합니다. 어떤 출처에서 어떤 버전이 들어왔는지 추적할 수 있고, 위변조된 스킬이 끼어드는 경로를 좁힙니다.

### 웹·모바일 클라이언트가 한층 풍부해졌습니다

컨트롤 UI에 세션 워크스페이스 레일이 새로 들어왔습니다. 동시에 여러 세션을 띄워 둔 사용자가 작업 공간을 시각적으로 잡기 좋아졌고, 확장(extension) 헬스 상태가 상태 표시에서 바로 보입니다. cron 리스트는 더 촘촘하게 정돈된 형태로 표시됩니다.

iOS에는 Watch 컨트롤이 추가됐습니다. 손목에서 가벼운 조작을 끝낼 수 있다는 뜻입니다. Android는 채팅 컨텍스트 사용량을 실시간으로 보여 줍니다. 컨텍스트가 어디까지 찼는지 직관적으로 확인할 수 있습니다.

### 검색·스킬·보안 정비

Codex Hosted Search가 새로 들어왔습니다. 키 없이 쓸 수 있는 검색 프로바이더는 여전히 명시적인 opt-in을 유지합니다. 보안 측면에서는 디버그·설정 출력에서 시크릿이 그대로 새지 않도록 마스킹 처리가 강화됐고, 내부 HTTP 세션 오버라이드가 차단됐습니다. 오픈 DM 도구 노출 감사와 플러그인 쓰기 권한 소유자 검증도 그대로 유지됩니다.

저장소와 마이그레이션 쪽에서는 네트워크 파일시스템에서 SQLite WAL을 사용하지 않도록 막았고, 재인덱스 사이드카(rollback journal)를 안전하게 교체합니다. 기본 에이전트 인증 프로필을 SQLite로 이관하는 작업도 들어갔습니다. CLI에서는 서브커맨드 뒤에 글로벌 플래그를 받도록 했고, CJK IME 합성 입력이 끊기지 않습니다. 운영 측면에서는 매니지드 Gateway 업데이트가 실패해도 재시작이 자연스럽게 이어지고, cron 전달 기본값이 안전한 쪽으로 유지됩니다.

## 실무자가 볼 핵심 포인트

운영자가 가장 먼저 확인할 부분은 텔레그램입니다. 그동안 표가 깨지거나 진행 메시지가 단조롭다는 피드백이 있었다면 6.9로 올린 직후 다시 확인해 볼 가치가 있습니다. 모바일에서 메시지가 어떻게 보이는지 한 번 더 점검하면, 대시보드를 굳이 열지 않아도 되는 영역이 늘어납니다.

에이전트 복원력 수정은 사일런트 실패를 줄여 줍니다. 평소에 "답이 멈췄다"는 보고가 있었다면 6.9에서 줄어들 가능성이 높습니다. 컴팩션 뒤에 사용량이 잘못 잡히던 문제도 같이 해소되니, 비용 가시화 기능을 쓰는 팀이라면 보고가 더 정확해진다는 점도 챙겨 두세요.

Codex 자동 승인은 양날의 검입니다. 자동화가 편해지는 만큼 어떤 플러그인이 자동 통과인지 정책을 한 번 정리하고 들어가는 게 안전합니다. 원격 노드 `exec`가 동적 도구로 풀린 것도 같은 맥락에서, 어떤 노드에 어떤 권한이 묶여 있는지 미리 확인해 두는 것을 권합니다.

마지막으로 외부 프로바이더 플러그인이 npm에서 독립적으로 발행된다는 점은 장기 운영에 의미가 큽니다. 본체와 분리된 라이프사이클을 가지게 됐기 때문에, 본체 업데이트를 미루는 동안에도 특정 프로바이더만 빠르게 올릴 수 있는 길이 열렸습니다. 반대로 버전 호환성 추적은 약간 더 꼼꼼해질 필요가 있습니다.
