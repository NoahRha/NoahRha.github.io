귀를 닫지 않는 음성 모델이 새로 나왔습니다. 사람이 말하는 동안에도 계속 듣고, 짧은 시간마다 “지금 말할 차례인가, 그냥 들을 차례인가”를 모델이 스스로 결정합니다.

중국·홍콩·싱가포르 연구진이 발표한 오픈소스 모델 Audio-Interaction은 0.4초 단위로 오디오를 잘라 보면서 응답할지 침묵할지 선택합니다. 파라미터는 30억 개. Apache 2.0 라이선스로 코드와 가중치가 공개됐고, 데이터셋도 곧 풀린다고 합니다.

## 핵심 요약

- The Decoder는 Audio-Interaction을 “끊김 없이 듣고 0.4초마다 말할지 침묵할지 결정하는 오픈소스 음성 모델”이라고 소개했습니다.
- 모델은 오디오 스트림을 0.4초 세그먼트로 잘라 매 구간마다 `<silent>` 또는 `<response>` 토큰을 출력합니다.
- 큐 기반 병렬 처리 구조로 첫 응답까지 평균 392ms, 같은 모델이 직렬 처리로 돌면 831ms로 늘어납니다.
- 핵심 데이터셋 StreamAudio-2M은 약 302,000시간, 260만 단위의 학습 자료로 7개 능력 영역과 28개 하위 과업을 다룹니다.
- MMAU 점수 58.15점으로 기반 모델 Qwen2.5-Omni-3B를 근소하게 넘었고, ProactiveSound Bench에서는 Gemini 3 Flash, Kimi-Audio-Instruct, Step-Audio 2를 앞섰습니다.
- 대화, 번역, 전사, 환경음 인식까지 한 모델에서 처리해, “녹음 종료 버튼이 달린 받아쓰기 기계”라 불리던 기존 음성 LLM 구조와 결을 달리합니다.

## 0.4초마다 듣고 결정한다는 의미

Audio-Interaction이 풀고 싶은 문제는 단순합니다. 사람이 말하고 끝낼 때까지 묵묵히 기다리는 것이 아니라, 듣는 도중에도 “지금 끼어들지 말지”를 모델이 결정하는 일입니다. 연구진은 입력 오디오를 0.4초 길이의 세그먼트로 잘라 모델에 흘려보냅니다. 모델은 한 세그먼트가 끝날 때마다 두 토큰 중 하나를 출력합니다. 계속 들으라는 `<silent>`이거나, 지금부터 답하라는 `<response>`입니다.

세그먼트 크기는 단순히 작게 한다고 좋아지지 않습니다. 0.2초로 줄이면 맥락이 모자라 대화가 끊기고, 0.8초로 늘리면 첫 응답까지 시간이 786ms로 길어집니다. 0.4초는 그 사이에서 균형이 가장 잘 잡히는 지점이었습니다.

이 구조 덕분에 모델은 사람이 잠시 숨을 고르거나 갑자기 다른 화제로 넘어갈 때 더 자연스럽게 반응할 수 있습니다. 그리고 “끝났다”는 신호 없이도 의미 있는 응답을 시작할 수 있습니다.

## 응답 392ms를 만들어낸 큐 기반 병렬 구조

지연 시간 392ms는 모델 가중치만으로 나오는 숫자가 아닙니다. 같은 모델이라도 처리 구조가 직렬이면 같은 작업이 831ms까지 늘어났습니다. 다운타임 비율도 5.2%로 올라갔습니다.

연구진은 듣기와 말하기를 분리된 공유 큐에서 동시에 굴리는 구조를 택했습니다. 한 쪽 큐는 오디오 입력을 끊김 없이 받고, 다른 쪽 큐는 모델 출력을 생성합니다. 두 흐름이 같은 데이터 큐를 공유하면서도 서로를 막지 않기 때문에, 사용자가 말하는 동안에도 모델은 다음 응답 토큰을 준비할 수 있습니다.

대화형 인터페이스에서 392ms와 831ms는 체감 차이가 큽니다. 같은 모델 가중치라도 파이프라인을 어떻게 짜느냐가 “쓸 만한 비서”와 “느린 자막기” 사이를 가르는 셈입니다.

## 302,000시간 학습 데이터와 두 가지 학습 함정

이 모델을 떠받치는 데이터셋이 StreamAudio-2M입니다. 약 302,000시간 분량, 260만 단위의 학습 자료가 7개 능력 영역과 28개 하위 과업으로 나뉘어 있습니다. 흥미로운 점은 데이터 대부분이 합성으로 만들어졌다는 것입니다.

연구진은 세 단계로 데이터를 생성했습니다. 먼저 언어 모델로 대화 시나리오를 설계하고, 그 시나리오에 맞는 오디오 클립을 찾거나 합성하고, 마지막으로 발화 전환이 자연스럽게 이어지도록 전처리했습니다.

학습 과정에서 두 가지 문제가 반복적으로 나타났습니다. 하나는 시끄러운 오디오 시퀀스가 길어질수록 모델이 앞부분 대화를 잊어버리는 장기 기억 문제입니다. 연구진은 앞 구간 내용을 묻는 질문을 일부러 학습 데이터에 섞어 이 문제를 줄였습니다. 다른 하나는 의미 없는 소리에 반응해 답을 시작해 버리는 오반응 문제입니다. 이 경우에는 침묵, 배경음 같은 “말이 아닌 소리” 구간을 많이 넣고, “이런 입력에는 반응하지 말라”고 명시적으로 표시해 학습시켰습니다.

벤치마크 결과는 흥미롭습니다. MMAU에서는 58.15점으로 기반 모델 Qwen2.5-Omni-3B를 살짝 넘는 수준이었습니다. 점수 자체보다 더 눈에 띄는 건 ProactiveSound Bench입니다. 어떤 소리에 반응해야 하는지 판단하는 이 평가에서 Audio-Interaction은 Gemini 3 Flash, Kimi-Audio-Instruct, Step-Audio 2를 앞섰습니다.

## 기존 음성 인터페이스와의 차이

The Decoder는 기존 멀티모달 음성 모델을 “버튼이 달린 받아쓰기 기계”에 비유했습니다. GPT-4o나 Qwen 3.5-Omni 같은 모델은 녹음이 끝나야 응답을 시작합니다. 사용자가 “이제 끝났어”라고 알려주거나 시스템이 무음 구간으로 종료를 감지해야 비로소 다음 단계로 넘어갑니다.

스트리밍 계열도 있지만 한계가 분명합니다. Moshi는 대화에 집중하고, Paraformer는 자막에 집중하는 식으로 한 가지 작업에 묶여 있습니다. 환경 소음, 음악, 알람 같은 비음성 신호는 대부분 배경 잡음으로 흘려보냅니다.

Audio-Interaction은 이 둘을 합치려는 시도입니다. 대화, 번역, 전사, 환경음 인식을 한 모델 안에서 같은 토큰 체계로 다룹니다. 그래서 “지금 들리는 게 사람 말인지, 알람인지, 그냥 소음인지”를 모델이 판단하고, 거기에 맞춰 답하거나 침묵합니다.

## 실무자가 볼 핵심 포인트

1. 음성 인터페이스의 다음 라운드는 모델 정확도가 아니라 “언제 말할지” 결정 구조에서 갈립니다. 끝나는 시점을 감지하는 무음 검출에 기대지 않고, 짧은 단위로 발화 권한을 모델이 결정하는 설계를 살펴볼 시점입니다.
2. 같은 모델이라도 파이프라인이 직렬이면 응답이 두 배 가까이 느려집니다. 음성 비서, 콜센터, 회의 보조 같은 제품을 만들 때 큐 기반 병렬 구조와 다운타임 비율을 처음부터 설계에 포함해야 합니다.
3. 학습 데이터에서 “반응하지 말 것”을 명시적으로 가르치는 접근은 보이스 봇의 오반응 문제를 줄이는 데 그대로 적용할 수 있습니다. 침묵·배경음 구간을 negative example로 강하게 넣는 방식이 핵심입니다.
4. 오픈소스 라이선스와 학습 데이터까지 공개될 예정인 점도 의미가 큽니다. 사내 음성 비서나 실시간 회의 도구처럼 폐쇄망에서 돌려야 하는 영역에서, 큐 기반 스트리밍 구조의 베이스라인으로 검토해볼 수 있습니다.

핵심은 결국 “듣는 동안에도 결정하는” 구조입니다. 음성 AI가 사람과 가까워질수록, 모델이 언제 말할지 스스로 정하는 능력이 점점 더 중요한 차별점이 될 것 같습니다.
